Alpi Maps: unified route design MOCKUP, fake data, icons are placeholders (the app uses mdi)

Companion to 00-unified-design.md. Same tokens and idioms as docs/design/mockups.html (stat tiles, pills, outlined warnings, panel header, round map controls, grouped rows). Use the buttons to switch the whole page between light, dark and e-ink. Sections in the route page frames are real <details>: click to collapse. Example route: Col du Granier loop, road bike, 62.4 km, leaves Sat 2 Nov 14:00, "now" is Sat 12:10.

1. Information architecture

Three surfaces read one stored RouteAnalysis. The sheet is a glance, the page is where depth and planning live, the map shows one dimension at a time.

Entry pointssheet Insights chip or tile tap, action, routes list row menu, directions result, "Ride saved" sheet, navigation start line
Route sheet (glance)5 tiles, profile + ribbon chips, Insights card, actions. Never grows a card per feature.
Route page (plan + analyse)Plan card (activity, departure, pace), pinned profile, 6 collapsible sections, saved data, Done mode.
Mapone colour mode (Plain, Surface, Grade, Steep, Risk, Sun, Weather) + that mode's symbols. Same mode in navigation.
Navigationremaining route only: risk banner, "Next 2 h" outlook, ETA from the re-anchored timeline.
RouteAnalysis (on the Item, offline)inputs: activity, departure, pace, geometryKey. Layers with provenance: terrain, risk, weather, sun. Derived on read: steep, climbs, risk level, sun state, wind, best departure.
RouteTimelinevertex index → seconds since departure. The only ETA source for weather, sun, navigation.
Freshnessfresh / aging / stale / inputs-changed / offline-cached / failed / pinned. Outlined chip, one refresh affordance, never blocks.
ProvidersValhalla (risk, surfaces), Open-Meteo behind WeatherProvider (forecast, past), SDK route sun API (terrain), suncalc (astronomy).

Freshness rules (summary)

Deterministic (terrain, steep, climbs, risk classification, sun astronomy): never old; recomputed silently if geometry / options change.
Static until change (risk candidates, surfaces): no age; "map data of <date>" in details.
Recomputable offline (sun terrain): auto-recompute when the timeline changes (native, debounced).
Fetched (weather, sun clouds): TTL by lead time:
lead to rideagingstale
in progress30 min60 min
≤ 24 h1 h3 h
24–72 h3 h6 h
> 72 h6 h12 h
Past / pinned: frozen, source named ("Reconstructed · ERA5 25 km").

5. Done ride: save with data, past weather

After a recording ends (or on an imported GPX with times) the page opens in Done mode: recorded timeline, past weather from Open-Meteo's Historical Forecast API (2021–2022 onward, ~1–5 km models) or ERA5 reanalysis (since 1940, ~25 km, 5-day delay), sun by astronomy + terrain. Everything is labelled as reconstructed, pinned, and never ages.

6. Map: one colour mode at a time, per-mode symbols

Line channel = exactly one mode (casing constant, dash reserved for status). Symbol channel = marks belonging to the active mode. Warning modes (Steep, Risk) share an amber-to-red ramp; descriptive modes use their own palettes; the app accent is never a mode colour. E-ink: black slice with white ticks (none / sparse / dense / solid) = severity, plus the same symbols. Click the mode pills in the first frame.

Computed at 09:05, left at 14:00: data is shown with its age, the timeline is re-anchored on the position (t' = now + (t(i) − t(here)) / pace factor), samples behind the rider are dropped.
