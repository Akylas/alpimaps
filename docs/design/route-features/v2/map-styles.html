README-v2 section 6. These are drawings of what dev_assets/styles/inner/shared/routelens.mss + the base-style changes should produce, not SDK screenshots. Every colour comes from one palette table (lens_pal style parameter), the same one the legend reads. Use the toolbar to see light / dark / e-ink; section 3 shows the three side by side.

1. Route anatomy (selected route, z15)

Casing (line-border, lens_case) → lens core (slices, severity also widens the line) → focus halo (theme accent, under the core) → direction marks → symbols. Dash stays reserved for status (detour, original, editing, connector), never for a lens.

2. The six lenses on the map (whole route)

Exactly one lens colours the line. Overview keeps the item colour and shows only safety symbols. The hiking / biking network overlay is dimmed while a lens ≠ Overview is active (base change B1), so its reds and purples do not compete.

3. Light / dark / e-ink side by side

Dark: casing turns dark (#101316) and every palette step is lifted so the line does not read as a hole. E-ink: black core 2 dp wider, white ticks whose density is the severity (sparse s1 · dense s2 · almost solid s3), plates black / white.

4. Symbols (plates use the fork's text-background-* / shield-*, no bitmaps)

5. Focus: tap a section anywhere

The app re-emits the slices with f = 0 outside the focused section (35 % opacity; e-ink: no translucency, 2 dp thinner and without ticks) and adds one lensfocus line (accent halo; e-ink: dotted black band). ≤ 200 features, rebuilt on focus change only.

6. Navigation layers

While navigating or following a route, slices are emitted into #navigation (under #maneuver) at navigation widths, in the planning lens (one shared lens). On top, whatever the lens, the alert overlay: fast-road runs get a red outer casing + speed sign, steep runs (≥ 9 %) get white chevrons. Weather plates only in the Weather lens. Travelled part greyed only if the split passes the perf gate (README 6.6). Speed signs grow to 28 dp.
